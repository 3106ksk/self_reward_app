# LP 使い方解説セクション設計書

## 目的

この設計書は、LPをスクロールしたときに、初めてミチシルベを見た人でも「何を入力し、どう使い、何が嬉しいのか」を混乱なく理解できるようにするための使い方解説セクションを整理するもの。

実装は含めない。`docs/lp_tone_palette_design.md` のトンマナ・カラーパレットを前提に、LP中盤から下部に追加する説明コンテンツの設計を定義する。

## 前提となる現在の実装

現在のアプリ画面は、大きく以下の2領域で構成されている。

### 左側: 設定パネル

ユーザーは左側の設定パネルから、ロードマップの材料を入力する。

- 価値観設定
  - フォーム項目: 価値観
  - 役割: なぜこのゴールを目指すのかを残す
- 長期ゴール設定
  - フォーム項目: 長期ゴール、長期ゴールの説明・理想状態
  - 役割: 最終的に到達したい目的地を置く
- サブゴール設定
  - フォーム項目: サブゴール名、説明・メモ、大きなご褒美、大きなご褒美の説明・メモ
  - 役割: 目的地までの通過点と、節目のご褒美を置く
- クエスト設定
  - フォーム項目: クエスト名、説明・メモ、関係するサブゴール選択
  - 役割: サブゴール達成に必要な条件を置く
- 小さなご褒美設定
  - フォーム項目: ご褒美名
  - 役割: クエストクリア時に選ぶ小さな報酬を用意する

### 右側: ゴールマップ

入力内容はマップ上に反映される。

- 価値観は、マップ上部のメッセージとして表示される
- サブゴールは、ルート上の通過点として表示される
- 最初のサブゴールには「現在地」が表示される
- クエストは、各サブゴールの下に表示される
- クエストは「未クリアクエスト」と「クリア済みクエスト」に分かれる
- サブゴールごとに「大きなご褒美」地点が表示される
- 全クエストをクリアすると、大きなご褒美を獲得できる

## LPで解決したい混乱

初見ユーザーは、以下で迷いやすい。

- Todoアプリなのか、目標管理アプリなのか分からない
- 「価値観」「長期ゴール」「サブゴール」「クエスト」の違いが分からない
- 何から入力すればよいか分からない
- クエストと毎日のTodoの違いが分からない
- 小さなご褒美と大きなご褒美の違いが分からない
- アプリを毎日どう使えばよいか分からない
- 休むこととご褒美が、学習継続にどう関係するか分からない

LPの使い方解説では、機能一覧ではなく「最初の利用体験」を順番に見せる。

## 説明設計の基本方針

### 伝える順番

初めての人には、実装上のフォーム順に近い以下の順番で説明する。

```text
1. 目指す理由を書く
2. 長期ゴールを置く
3. サブゴールに分ける
4. クエストを作る
5. 小さなご褒美を用意する
6. 学習後にクエストをクリアする
7. サブゴール達成で大きなご褒美を受け取る
```

### 強調する考え方

- 毎日Todoを作る必要はない
- クエストは、サブゴール達成に必要な条件
- 学習したあとに「どのクエストが進んだか」を確認する
- ご褒美は、頑張りを釣るものではなく、前進を認めるためのもの
- マップを見ることで、今どこにいて、どこへ向かっているか分かる

### 避ける説明

- 「毎日のタスクを登録しましょう」
- 「学習時間を記録しましょう」
- 「連続記録を伸ばしましょう」
- 「報酬を稼ぎましょう」
- 「未達をなくしましょう」

## LPに追加する推奨セクション

## 1. 使い方導入セクション

### 目的

ヒーローとコンセプトを読んだ後に、「具体的にどう使うのか」を一言で理解させる。

### 見出し

使い方は、道のりを置いて、進んだ地点を確認するだけ。

### 本文

ミチシルベでは、毎日のTodoを増やすのではなく、目指す未来までの道のりを先に作ります。学習したあとは、進んだクエストをクリアして、今日の前進をマップ上で確認します。

### 表示イメージ

- 左に短い説明文
- 右に「価値観 → 長期ゴール → サブゴール → クエスト → ご褒美」の簡易ロードマップ
- 各地点を既存パレットの色で表現する

### 使用色

- 価値観: `Inner Compass`
- 長期ゴール: `Horizon Blue`
- サブゴール: `Landmark Yellow`
- クエスト: `Current Green`
- ご褒美: `Rest Amber`

## 2. 初期設定ステップセクション

### 目的

アカウント作成後に何を入力するのかを迷わせない。

### 見出し

最初に作るのは、あなた専用の学習マップ。

### ステップ

| Step | タイトル | 説明 | 実装との対応 |
| --- | --- | --- | --- |
| 01 | 価値観を書く | なぜそのゴールを目指すのか、大切にしたい理由を残します。 | 価値観設定 |
| 02 | 長期ゴールを置く | 最終的に到達したい状態を目的地として設定します。 | 長期ゴール設定 |
| 03 | サブゴールに分ける | 遠い目的地までの道のりを、通過点に分けます。 | サブゴール設定 |
| 04 | クエストを作る | サブゴール達成に必要な条件を登録します。 | クエスト設定 |
| 05 | ご褒美を用意する | 小さな前進と大きな節目を、自分で認める準備をします。 | 小さなご褒美設定、サブゴールの大きなご褒美 |

### UI表現

横並びカードよりも、縦方向のステップ表示が向いている。理由は、ユーザーが入力順を上から追えるため。

推奨レイアウト:

- 左: ステップ番号と説明
- 右: そのステップでマップ上に追加される要素の小さなプレビュー
- モバイルでは1カラムにする

### 注意点

「全部を完璧に入力する必要はない」と伝える。初期設定が重く見えると離脱しやすい。

補足コピー例:

> 最初は仮の内容でも大丈夫。学習しながら、あとで何度でも見直せます。

## 3. クエスト説明セクション

### 目的

クエストが毎日のTodoではないことを明確にする。

### 見出し

クエストは、今日やるTodoではなく、できるようになりたい条件。

### 本文

たとえば「Rails基礎を理解する」というサブゴールなら、「CRUDアプリを1つ作る」「バリデーションを使える」「ログイン機能を実装する」のように、達成条件をクエストとして置きます。毎日新しいTodoを作らなくても、学習後に進んだクエストを確認できます。

### 例示

```text
長期ゴール:
Webエンジニアに転職する

サブゴール:
Rails基礎を理解する

クエスト:
- CRUDアプリを1つ作る
- バリデーションを使えるようにする
- アソシエーションを説明できる
- ログイン機能を実装する
```

### UI表現

左右比較は分かりやすい。

左:

- 今日のTodo
- 毎日追加する
- 未完了が残ると焦る

右:

- クエスト
- 達成条件として置く
- できるようになったらクリアする

ただし、Todoを強く否定しすぎない。ミチシルベの違いを伝える程度にする。

### 推奨コピー

> Todoを消すためではなく、できるようになったことを確認するために。

## 4. 日々の使い方セクション

### 目的

アプリを毎日どう使うのかを具体化する。

### 見出し

学習したあと、今日の前進をマップに戻す。

### 利用フロー

```text
1. 学習する
2. マップを開く
3. 今向かっているサブゴールを見る
4. 進んだクエストを確認する
5. クリアできたら小さなご褒美を選ぶ
6. 今日はここまで、と休息へ切り替える
```

### 本文

ミチシルベは、学習前に細かい予定を作るアプリではありません。学習したあとに、今日の行動がどのクエストにつながったかを確認するための場所です。短い時間でも、クエストが一歩進めば、それは未来に向かう前進としてマップに残ります。

### UI表現

時系列の縦スクロールアニメーション風が合う。

- 「学習する」にはアプリ外の生活シーンを示す
- 「マップを開く」以降はアプリ画面のUI断片を示す
- 最後は `Rest Amber` のご褒美地点で終える

## 5. ご褒美説明セクション

### 目的

小さなご褒美と大きなご褒美の違いを理解させる。

### 見出し

ご褒美は、前進を認めて休むための区切り。

### 二段階の説明

| 種類 | タイミング | 役割 | 例 |
| --- | --- | --- | --- |
| 小さなご褒美 | クエストをクリアしたとき | 日々の前進を認める | 好きなドリンク、10分休む、動画を1本見る |
| 大きなご褒美 | サブゴールを達成したとき | 節目を祝う | 半日休む、本を買う、外食する |

### 本文

ご褒美は、学習時間を稼いだ対価ではありません。できるようになったこと、進めたことを自分で認めるための体験です。だから、ミチシルベではクエストクリアとサブゴール達成にご褒美を結びつけます。

### UI表現

- 小さなご褒美: クエストカード横の小さな光
- 大きなご褒美: サブゴール横の休憩地点
- どちらも派手な報酬演出にしない

## 6. マップの読み方セクション

### 目的

実際の画面を見たときに、各要素の意味が分かるようにする。

### 見出し

マップを見れば、今いる場所と次に向かう場所が分かる。

### 説明するラベル

| 表示 | 意味 |
| --- | --- |
| 価値観 | 目標を目指す理由 |
| 現在地 | 今向かっているサブゴール |
| サブゴール | 長期ゴールまでの通過点 |
| 未クリアクエスト | まだ進めている達成条件 |
| クリア済みクエスト | できるようになったこと |
| 大きなご褒美 | サブゴール達成時の節目 |
| 目的地 | 長期ゴール |

### UI表現

実際のアプリ画面のスクリーンショットまたはモックに、番号付きの吹き出しを重ねる。

吹き出しは多すぎると読みにくいので、最大5つに絞る。

推奨ラベル:

1. 価値観
2. 現在地
3. サブゴール
4. クエスト
5. ご褒美

## 7. 導入前の安心セクション

### 目的

初期設定への心理的ハードルを下げる。

### 見出し

最初から、きれいな計画にしなくていい。

### 本文

目標やクエストは、学習しながら変わっていくものです。ミチシルベでは、価値観、長期ゴール、サブゴール、クエストをあとから見直せます。まずは今の言葉で、最初の道しるべを置くところから始められます。

### 表現方針

このセクションは強いCTAより、安心感を出す。完璧主義のユーザーに向けて、入力の正解を探さなくてよいと伝える。

## LP全体の推奨スクロール構成

既存の `docs/lp_tone_palette_design.md` の構成に、使い方解説を挿入する場合は以下がよい。

```text
1. Hero
   - 今日の学習を、未来まで続く道のりに変える。

2. Problem
   - 頑張っているのに、進んでいる実感が持てない。

3. Concept
   - Todoを増やすより、進んでいる方向を見失わない。

4. Usage Intro
   - 使い方は、道のりを置いて、進んだ地点を確認するだけ。

5. Initial Setup Steps
   - 最初に作るのは、あなた専用の学習マップ。

6. Quest Explanation
   - クエストは、今日やるTodoではなく、できるようになりたい条件。

7. Daily Usage
   - 学習したあと、今日の前進をマップに戻す。

8. Reward Explanation
   - ご褒美は、前進を認めて休むための区切り。

9. Map Reading
   - マップを見れば、今いる場所と次に向かう場所が分かる。

10. CTA
   - まずは、目指す未来と最初の中継地点を置く。
```

## セクション別コピー案

### Usage Intro

見出し:

> 使い方は、道のりを置いて、進んだ地点を確認するだけ。

本文:

> まずは価値観、長期ゴール、サブゴール、クエストを置いて、自分だけの学習マップを作ります。学習したあとは、進んだクエストをクリアして、今日の前進をマップに戻します。

### Initial Setup

見出し:

> 最初に作るのは、あなた専用の学習マップ。

本文:

> 目指す理由、目的地、通過点、達成条件を順番に置くだけで、長期学習の道のりが見えるようになります。

### Quest Explanation

見出し:

> クエストは、今日やるTodoではなく、できるようになりたい条件。

本文:

> 毎日細かいタスクを増やす代わりに、サブゴール達成に必要な条件をクエストとして置きます。学習を通じてできるようになったら、クエストをクリアします。

### Daily Usage

見出し:

> 学習したあと、今日の前進をマップに戻す。

本文:

> 短い学習でも、どのクエストにつながったかが分かれば前進として残せます。今日できたことを確認したら、小さなご褒美を選んで休息へ切り替えます。

### Reward Explanation

見出し:

> ご褒美は、前進を認めて休むための区切り。

本文:

> クエストをクリアしたら小さなご褒美。サブゴールを達成したら大きなご褒美。頑張りを稼ぐ仕組みではなく、進んだ自分を認めるための体験です。

### Map Reading

見出し:

> マップを見れば、今いる場所と次に向かう場所が分かる。

本文:

> 価値観、現在地、サブゴール、クエスト、ご褒美、目的地が一枚のマップでつながります。迷ったときも、どこへ向かっているのかをすぐに確認できます。

## UI表現の注意

- 説明セクションでもカードを多用しすぎない
- 手順はカード一覧ではなく、道筋やステップとして見せる
- 見出しは短く、本文は2から3行に収める
- 「入力が多いアプリ」に見えないようにする
- フォーム項目をそのまま羅列しすぎない
- 各セクションに必ず「マップにどう反映されるか」を入れる
- 「クエスト」と「ご褒美」の説明は、ゲーム感よりも前進感・休息感を優先する

## モバイル表示方針

モバイルでは、使い方説明が長く見えやすい。以下の構成にする。

- 1セクション1メッセージ
- ステップは縦並び
- 1ステップの説明は最大2行
- 図解は横スクロールにしない
- マップの読み方は、スクリーンショット全体ではなく重要箇所を切り出す
- CTAは各説明後ではなく、最後に1つ置く

## 最終方針

LPの使い方解説は、機能説明ではなく「初めて使う日の流れ」として見せる。

ユーザーがLPを読み終えたときに、以下を理解できる状態を目指す。

- 最初に価値観と長期ゴールを置く
- 目的地までをサブゴールに分ける
- サブゴール達成に必要なクエストを作る
- 学習後にクエストをクリアする
- クエストクリアで小さなご褒美を選ぶ
- サブゴール達成で大きなご褒美を受け取る
- マップを見ることで、現在地と次の行き先が分かる

最も重要なのは、初見ユーザーに「毎日Todoを増やすアプリ」ではなく、「長期学習の道のりを見失わないためのアプリ」と理解してもらうこと。
