# LP UI トンマナ・カラーパレット設計書

## 目的

この設計書は、ミチシルベのLPサイトを作成する前段階として、サービスの最新コンセプトと要件に合うカラーパレット、トンマナ、ビジュアル方針、コピー方針を整理するもの。

実装は含めない。LPのUIを作る際は、この設計書を基準にする。

## 参照した要件

- `concept_summary.md`
- `design_tone_palette.md`
- `docs/concept_decision_log.md`
- `docs/ui_prototypes/transit-map/design.md`
- 既存アプリUIの配色とマップ表現

特に最新要件では、以下の判断を重視する。

- 毎日のTodo管理アプリには見せない
- 学習時間をゴールドに変換する経済システムを主役にしない
- 長期ゴール、サブゴール、クエスト、ご褒美の構造を中心にする
- ご褒美は「稼いだ対価」ではなく「前進を認める体験」として扱う
- マップ上で現在地と道のりを確認できることを中心価値にする

## LPで伝えるべきサービス像

ミチシルベは、単なるTodo管理アプリでも、習慣化アプリでも、ご褒美交換アプリでもない。

LPでは、次のように伝える。

> 自分が目指す未来までの道のりを見える化し、毎日の学習を前進と報酬に変える、長期学習のためのロードマップアプリ。

中心に置く価値は「タスクを消化すること」ではなく、以下を見えるようにすること。

- なぜその目標を目指しているのか
- 長期ゴールまでの道のりはどうなっているのか
- 今どのサブゴールに向かっているのか
- サブゴール達成に必要なクエストは何か
- 日々の学習がどの前進につながっているのか
- 小さな達成を認め、休息やご褒美につなげられるか

## LP全体のトンマナ

### キーワード

- 静かな夜のロードマップ
- 現在地を照らす道しるべ
- 長期学習の旅
- 焦らせない前進感
- 休んでよいと感じられる区切り
- 都市的だが、冷たすぎない
- ゲームの構造を借りるが、ゲーム風にしすぎない

### 目指す印象

- 自分の現在地が分かる
- 目指す未来とのつながりが見える
- 短い学習でも意味があると感じられる
- 完璧主義の人を追い込まない
- ご褒美が軽薄な報酬ではなく、自分を労る体験に見える
- 休息がサボりではなく、道の途中にある必要な地点に見える

### 避ける印象

- 派手なRPG、ソーシャルゲーム、ガチャ風
- Todoリスト、タスク管理、業務ツール感
- 達成率、未達、連続記録、ランキングで追い込む表現
- ゴールドやポイントを稼ぐことが主役に見える表現
- 星空、月、星座モチーフへの寄せすぎ
- 本物の交通アプリ、乗換案内アプリへの寄せすぎ

## LP用メインコンセプト

### コンセプト名

夜明け前のロードマップ

### コンセプト説明

仕事や生活の合間に学習を続ける人が、暗い夜道で小さな灯りを頼りに進むように、自分の現在地、次の中継地点、最終目的地を確認できる世界観。

暗い背景は、不安や焦りを抱えながら学習する夜の時間を表す。ただし、重く沈ませるのではなく、道筋・現在地・クエスト・ご褒美が柔らかく灯ることで、「少しずつ進めている」という安心感を作る。

ゲームマップの分かりやすさは借りるが、宝箱やレベルアップ演出を前面に出しすぎない。報酬は派手な獲得演出ではなく、道の途中にあるカフェ、キャンプ、宿、スタンプのような静かな区切りとして扱う。

## パレットの使い方

### ベース配色

LP全体は `Deep Trail` を主背景にする。大きな面は暗く保ち、情報や道筋が浮かび上がるようにする。

`Distant Ridge` と `Night Harbor` は、セクションの切り替えやヒーロー背景の奥行きに使う。暗い青緑系に寄せるが、全体が単調な青黒だけにならないように、黄色、アンバー、紫を要所に置く。

### アクセント配色

- `Current Green`: 「今ここ」「進んだ」「クエストクリア」に使う
- `Horizon Blue`: 「長期ゴール」「未来」「目的地」に使う
- `Landmark Yellow`: 「サブゴール」「中継地点」「CTAの補助」に使う
- `Rest Amber`: 「ご褒美」「休息」「区切り」に使う
- `Inner Compass`: 「価値観」「目指す理由」に使う

CTAボタンは `Landmark Yellow` から `Rest Amber` へのグラデーションが最も相性がよい。学習を急かす緑ではなく、「道しるべを置く」「一歩始める」感覚を出せる。

### 避ける配色

- 紫と青だけのグラデーションで全体を作らない
- ベージュ、茶色、クリーム系を主役にしない
- 黒背景にネオンを強く当てすぎない
- 赤を通常の未達・遅れ表現に使わない

## タイポグラフィ方針

### 日本語

既存UIと同じく、丸みのある日本語書体を見出しに使うとサービスのやさしさと相性がよい。

推奨:

- 見出し: `"Hiragino Maru Gothic ProN", "Hiragino Sans", "Yu Gothic", system-ui, sans-serif`
- 本文: `"Hiragino Sans", "Yu Gothic", system-ui, sans-serif`

### 文字の印象

- 見出しは大きく、短く、強く
- 本文は行間を広めにして、安心して読める密度にする
- 英字ラベルは小さく使う
- 文字間は詰めない。`letter-spacing: 0` を基本にする

### 見出し例

- 今日の学習を、未来まで続く道のりに変える。
- Todoを増やすより、進んでいる方向を見失わない。
- 長期学習を、迷いにくい5つの地点へ。
- ここまで来たから、今日は休んでいい。

## ビジュアルモチーフ

### メインモチーフ

ロードマップ、道しるべ、現在地ピン、中継地点、遠くの灯り。

LPのファーストビューでは、実際のアプリ画面またはアプリ画面を抽象化したマップ表現を大きく見せる。単なるイラストではなく、サービスの中核である「価値観、長期ゴール、サブゴール、クエスト、ご褒美がつながる」ことを視覚化する。

### サブモチーフ

- 価値観: コンパス、北極星ではなく内側の針
- 長期ゴール: 遠くの街、丘の上の灯り、目的地マーカー
- サブゴール: ランドマーク、チェックポイント、橋
- クエスト: 小さな道標、足あと、点灯する地点
- ご褒美: カフェ、キャンプ、宿、スタンプ、チケット

### 避けるモチーフ

- 宝箱を主役にする
- コイン、ゴールド、ポイント残高を大きく見せる
- RPGキャラクターやモンスターを出す
- 電車、駅、路線図だけに見える表現
- 星空や星座を前面に出す

## LP構成案

### 1. Hero

目的:
サービスの第一印象で「長期学習のロードマップアプリ」と伝える。

表示内容:

- サービス名: ミチシルベ
- メインコピー: 今日の学習を、未来まで続く道のりに変える。
- サブコピー: 価値観・長期ゴール・サブゴール・クエストを一枚のマップでつなぎ、不安や焦りを減らしながら前進を実感するためのロードマップアプリ。
- CTA: マップを作成する

ビジュアル:

- 暗い背景にマップ画面または抽象マップを大きく配置
- 現在地、サブゴール、ご褒美地点、長期ゴールが柔らかく灯る
- ヒーローの下に次セクションが少し見える高さにする

### 2. Problem

目的:
想定ユーザーの課題に共感する。

見出し例:
頑張っているのに、進んでいる実感が持てない。

伝える内容:

- 仕事や生活の合間に学習している
- 短い時間しか取れず、成果が見えづらい
- 周りと比べて焦る
- 休んでいても罪悪感がある
- Todoを消しても、未来に近づいた感覚が薄い

### 3. Concept

目的:
Todo管理ではなく、現在地確認のサービスであることを明確にする。

見出し例:
Todoを増やすより、進んでいる方向を見失わない。

伝える内容:

- 価値観を起点にする
- 長期ゴールを目的地にする
- サブゴールを中継地点にする
- クエストを達成条件にする
- ご褒美を前進を認める体験にする

### 4. Roadmap Structure

目的:
最新要件の階層を視覚的に理解させる。

表示構造:

```text
価値観
  -> 長期ゴール
      -> サブゴール
          -> クエスト
              -> 小さなご褒美
```

サブゴール達成時:

```text
全クエストクリア
  -> サブゴール達成
      -> 大きなご褒美
```

### 5. Reward

目的:
ご褒美が主役になりすぎないようにしながら、サービスの魅力として伝える。

見出し例:
ご褒美は、頑張りを釣るためではなく、前進を認めるために。

伝える内容:

- クエストクリアで小さなご褒美
- サブゴール達成で大きなご褒美
- 学習時間を稼ぐ仕組みではない
- 休息への切り替えを助ける

### 6. CTA

目的:
最初の行動を明確にする。

見出し例:
まずは、目指す未来と最初の中継地点を置く。

CTA:
無料でマップを作成する

## UIディレクション

### レイアウト

- ヒーローは実サービス画面、またはマップビジュアルを背景として大きく使う
- カードを多用しすぎない
- セクションは広い余白を持つフル幅の帯として構成する
- 要素の説明はカードよりも、道筋・地点・ラベルとして見せる
- 情報密度はLPでは低め、アプリ画面ではやや高めにする

### 角丸・線・影

- 角丸は基本 `7px` から `8px`
- 丸すぎるカードやボタンは避ける
- 線は `Trail Line` を薄く使う
- 影は強くしすぎず、暗背景上で少し浮く程度

### ボタン

Primary CTA:

- 背景: `Landmark Yellow` から `Rest Amber`
- 文字: `#1D2A31`
- 文言: 「マップを作成する」「無料で始める」

Secondary CTA:

- 背景: 透明または薄い白
- 線: `rgba(245, 247, 239, 0.20)`
- 文言: 「ログイン」「コンセプトを見る」

### マップ表現

- ルート線は太すぎず、柔らかく点灯する
- 現在地は `Current Green`
- 長期ゴールは `Horizon Blue`
- サブゴールは `Landmark Yellow`
- ご褒美地点は `Rest Amber`
- 価値観は `Inner Compass`

## 実装時の注意

- LPは未ログインユーザー向け、アプリ本体はログイン後に分ける
- 既存のマップUIと断絶しないよう、同じ色名・同じ意味づけを使う
- Heroに使う画像は、実際のサービス画面が分かるものを優先する
- 文章量を増やしすぎず、短い見出しで感情と価値を伝える
- 「Todo」「学習時間」「ゴールド」を主語にしない
- 「クエスト」と「ご褒美」は楽しさを出すが、過度にゲーム化しない

## 最終方針

LPのデザインは、既存のミチシルベUIが持つ暗背景・マップ・道しるべの方向性を継承する。

ただし、最新要件に合わせて、路線図や今日のTodo感は弱める。代わりに、長期学習のロードマップとして「価値観、長期ゴール、サブゴール、クエスト、ご褒美」がつながる構造を主役にする。

ユーザーに与える第一印象は、以下にする。

> 頑張りを管理されるアプリではなく、自分が進んでいる道を確認し、安心して続けたり休んだりするためのアプリ。
